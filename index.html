Vercel Skills, explicado desde cero

Aprende qué son las Skills para agentes de IA, cómo instalarlas, cómo crear las tuyas y cómo evitar los errores más comunes. Todo con pasos concretos, ejemplos y advertencias de verificación.

La CLI instala la Skill; el agente la lee y la aplica cuando detecta que es relevante.

Antes de copiar un comando: verifica. Este tutorial se basa en una guía que marca expresamente los puntos que deben comprobarse. Los nombres exactos de subcomandos, flags, identificadores de agentes y rutas de instalación pueden cambiar entre versiones. La fuente de verdad es npx skills --help y el README oficial del proyecto. Cada vez que veas VERIFICAR, significa: compruébalo tú antes de usarlo en un entorno real.

Qué vas a aprender

1. Entender el ecosistema

Qué es una Skill, qué es un agente, qué hace la CLI y qué papel juegan GitHub, npm y el catálogo skills.sh.

2. Preparar el equipo

Comprobar Node.js, npm y Git; abrir una terminal y saber en qué carpeta estás trabajando.

3. Instalar Skills

Descubrir, inspeccionar e instalar una Skill en el agente correcto, a nivel de proyecto o de usuario.

4. Crear tus propias Skills

Escribir un archivo SKILL.md claro, con procedimiento, ejemplos y criterios de calidad.

5. Mantener y compartir

Actualizar, eliminar, organizar una biblioteca personal y publicar Skills en GitHub.

6. Trabajar con seguridad

Detectar instrucciones peligrosas, revisar procedencias y responder ante una Skill sospechosa.

Para quién es este tutorial

Sí es para ti si…

  • Usas o quieres usar asistentes de IA para programar, escribir o automatizar tareas.
  • Has oído hablar de “Skills”, “agentes” o “SKILL.md” y no sabes por dónde empezar.
  • Quieres que un agente siga siempre el mismo procedimiento sin repetírselo en cada conversación.
  • Prefieres instrucciones paso a paso, con resultados esperados y solución de problemas.

Qué necesitas

  • Un ordenador con Windows 11, macOS o Linux.
  • Node.js y npm instalados (te enseñamos a comprobarlo).
  • Una terminal y conexión a internet.
  • Un agente de IA compatible con el formato SKILL.md.
  • Git y una cuenta de GitHub solo si vas a publicar o usar repositorios privados.

No necesitas saber programar. Sí necesitas leer con atención y verificar los comandos.

Módulos 0, 2 y 7

Conceptos: qué es cada cosa y por qué importa

Antes de ejecutar comandos, necesitas separar siete elementos que los principiantes suelen confundir: la CLI, el repositorio, la Skill, el archivo SKILL.md, el agente, la carpeta de instalación y las instrucciones que el agente consulta.

1. ¿Qué es Vercel Skills?

Vercel Skills es un proyecto de código abierto mantenido por Vercel Labs. Está compuesto por dos piezas principales:

  1. Una CLI llamada skills, publicada en npm, que sirve para buscar, instalar, listar, actualizar y eliminar Skills para agentes de IA.
  2. Un catálogo público en https://skills.sh/, donde se pueden explorar Skills de la comunidad y de Vercel, organizadas por categorías, autor y repositorio de origen.

Una analogía útil: es como una tienda de aplicaciones + gestor de paquetes, pero para instrucciones que mejoran a un agente de IA, no para programas ejecutables.

Las tres piezas que no debes confundir
ConceptoQué esAnalogía

2. ¿Qué es una Skill?

Una Skill es una carpeta que contiene, como mínimo, un archivo llamado exactamente SKILL.md. Ese archivo incluye:

  • Una cabecera con metadatos (nombre, descripción, cuándo usarla).
  • Un cuerpo en Markdown con instrucciones, procedimientos, ejemplos y reglas.

Una Skill no es código que se ejecuta automáticamente. Es texto estructurado que un agente lee y usa como guía, igual que una persona nueva en un trabajo lee un manual de procedimientos antes de actuar.

Idea clave: una Skill no es un agente. Una Skill es información que un agente consulta. Sin un agente que la lea, es un archivo de texto inerte.

3. ¿Qué problema resuelve?

Antes de las Skills, si querías que un agente siguiera siempre el mismo procedimiento detallado, tenías que repetir las instrucciones en cada conversación, copiarlas en cada proyecto o confiar en que el agente “recordara” algo que normalmente no recuerda entre sesiones.

Las Skills permiten empaquetar instrucciones reutilizables en un formato estándar, instalarlas una vez y dejar que el agente las use cuando detecta que son relevantes.

4. Skill vs. prompt vs. plugin vs. herramienta vs. agente

Diferencias prácticas
ElementoQué haceSe instala o se escribePermanece entre sesiones
PromptUn mensaje puntual que escribes tú en una conversación.Se escribe cada vez.No, salvo que lo guardes.
SkillUn conjunto reutilizable de instrucciones guardado en un SKILL.md.Se instala una vez en una carpeta.Sí, mientras el archivo exista.
Plugin / extensiónAñade funciones nuevas al programa, normalmente con código ejecutable.Se instala en el programa anfitrión.Sí, actúa a nivel de software.
Herramienta (tool)Una función concreta que el agente puede ejecutar: leer archivos, buscar, ejecutar código.La proporciona el agente o un plugin.Depende del agente.
AgenteEl programa completo que usa un modelo de IA, lee Skills y ejecuta herramientas.Se instala como aplicación o CLI.Es el anfitrión de todo lo demás.

Resumen en una frase: una Skill es como una página de un manual que el agente saca de un archivador cuando la necesita; el agente es la persona que trabaja; las herramientas son sus manos; un plugin amplía sus capacidades físicas; un prompt es una orden verbal puntual.

5. La arquitectura en siete elementos

  1. El programa skills: la CLI que tú ejecutas en la terminal. No es una Skill.
  2. El repositorio que contiene Skills: un proyecto en GitHub donde se publican una o varias carpetas de Skills.
  3. Una Skill individual: una carpeta concreta dedicada a una sola habilidad.
  4. El archivo SKILL.md: el archivo principal con la cabecera y las instrucciones.
  5. El agente que utiliza la Skill: el programa de IA que lee el archivo y decide si lo aplica.
  6. La carpeta de instalación: la ubicación del disco donde la CLI copia la Skill para que el agente la encuentre.
  7. Las instrucciones que el agente consulta: el contenido del SKILL.md y de sus archivos auxiliares.
Repositorio GitHub → CLI skills → Carpeta del agente → Agente de IA → Resultado

6. Anatomía de un archivo SKILL.md

El archivo tiene dos partes: una cabecera YAML delimitada por tres guiones y un cuerpo en Markdown.

Campos de la cabecera
CampoObligatorioDescripción
nameSíNombre identificativo, corto y descriptivo, normalmente en minúsculas y con guiones.
descriptionSíExplica qué hace y cuándo debe activarse. Es el campo más importante: el agente lo usa para decidir si la Skill es relevante.
licenseOpcionalLicencia de distribución. Su tratamiento exacto depende del agente o la herramienta.
Otros camposOpcionalAlgunos agentes admiten campos propios. Verifica siempre en la documentación de tu agente antes de asumir que tendrán efecto.

Ejemplo completo y funcional

---
name: resumen-de-reuniones
description: Genera un resumen estructurado de las notas de una reunión, identificando decisiones tomadas, tareas asignadas y responsables. Úsala cuando el usuario pida "resume esta reunión", "saca las tareas de esta transcripción" o pegue notas de una reunión.
---

# Resumen de reuniones

## Cuándo usar esta skill

Usa esta skill cuando el usuario:
- Pegue una transcripción o notas de una reunión y pida un resumen.
- Pida explícitamente extraer tareas, decisiones o responsables de un texto de reunión.

## Procedimiento

1. Lee el texto completo proporcionado por el usuario.
2. Identifica y separa tres bloques:
   - Decisiones tomadas.
   - Tareas asignadas (con responsable, si se menciona).
   - Temas pendientes de resolver.
3. Redacta el resumen usando el siguiente formato:

   ## Resumen de la reunión
   ### Decisiones
   - ...
   ### Tareas
   - [Responsable] Tarea...
   ### Pendientes
   - ...

4. Si no se menciona un responsable para una tarea, indica "(sin asignar)".
5. No inventes decisiones ni tareas que no estén explícitas o claramente implícitas en el texto original.

## Criterios de calidad

- El resumen no debe superar el 25% de la longitud del texto original.
- Cada tarea debe tener un verbo de acción claro.
- No se debe omitir ninguna decisión explícita del texto original.

## Ejemplo

**Entrada (fragmento):**
"Quedamos en que María se encarga del informe para el viernes. Todavía no decidimos el presupuesto final."

**Salida esperada:**
## Resumen de la reunión
### Decisiones
- (ninguna decisión final registrada sobre presupuesto)
### Tareas
- [María] Entregar el informe antes del viernes.
### Pendientes
- Definir el presupuesto final.
Por qué este ejemplo funciona bien
  • Descripción con frases disparadoras: incluye expresiones que un usuario real escribiría.
  • Procedimiento numerado: el agente sabe qué hacer y en qué orden.
  • Criterios verificables: “no superar el 25%” es comprobable; “que quede bien” no lo es.
  • Manejo de datos faltantes: indica “(sin asignar)” en lugar de inventar responsables.
  • Ejemplo de entrada y salida: reduce la ambigüedad sobre el formato esperado.

7. Cómo decide el agente activar una Skill

De forma general, el agente escanea las carpetas donde pueden existir Skills instaladas, lee las cabeceras (name y description) para construir un índice ligero y, cuando planteas una tarea, compara esa tarea con las descripciones. Si decide que una Skill es relevante, carga su contenido completo y lo usa como guía.

El comportamiento exacto depende de cada agente. Algunos pueden permitir invocarla explícitamente por nombre; otros dependen solo de la detección automática. Verifica la documentación de tu agente.

8. Instalación de proyecto vs. instalación global

Dos alcances distintos
TipoDónde quedaQuién puede usarlaCuándo conviene

9. Qué puede y qué no puede hacer una Skill

Puede

  • Guiar al agente con procedimientos detallados.
  • Aportar ejemplos, plantillas y listas de comprobación.
  • Referenciar archivos auxiliares.
  • Indicar qué herramientas usar y en qué orden, si el agente las tiene.

No puede por sí sola

  • Ejecutar código de forma autónoma: quien actúa es el agente y sus herramientas.
  • Garantizar que el agente la siga al pie de la letra.
  • Funcionar sin un agente compatible que la cargue.
  • Sustituir la supervisión humana en tareas sensibles.

10. Resumen del módulo

  • La CLI instala; el catálogo descubre; el repositorio contiene; el agente aplica.
  • Una Skill es una carpeta con un SKILL.md.
  • La description es la puerta de entrada: decide si la Skill se activa.
  • Instalar la CLI no instala ninguna Skill.
  • Instalar una Skill no garantiza que el agente la use si no es relevante o si está en la carpeta equivocada.

Procedimiento: de cero a una Skill instalada

Esta es la parte práctica. Sigue los pasos en orden. Cada paso incluye objetivo, explicación, comandos, resultado esperado y problemas probables.

Protocolo obligatorio antes de ejecutar. Los comandos de esta sección siguen el patrón documentado y habitual de este tipo de CLIs, pero los nombres exactos pueden variar. 0

Verificar la CLI y la documentación

Objetivo: conocer los comandos reales de tu versión antes de confiar en cualquier tutorial.

La ayuda integrada refleja exactamente la versión que se está ejecutando en tu ordenador. Es más fiable que cualquier guía, incluida esta.

npx skills --help
npx skills add --help

Resultado esperado: una lista de subcomandos y opciones. Si add --help no existe, prueba con el subcomando que aparezca en la ayuda general.

Problema probable: si no aparece nada, revisa Node.js y tu conexión (paso 1).

1

Comprobar requisitos: Node.js, npm y Git

Objetivo: asegurarte de que la CLI puede ejecutarse.

La CLI está publicada en npm y necesita Node.js. Git es opcional para instalar Skills existentes, pero recomendable para clonar repositorios o publicar los tuyos.

node -v
npm -v
git --version

Resultado esperado: números de versión, por ejemplo v20.11.0 y 10.2.4. En Git, algo como git version 2.x.

Si falla: instala Node.js desde nodejs.org, elige la versión LTS, acepta las opciones por defecto, cierra y vuelve a abrir la terminal. Git se instala desde git-scm.com.

En Windows, si acabas de instalar Node.js y la terminal sigue sin reconocerlo, reinicia la terminal y, si persiste, cierra sesión y vuelve a entrar.

2

Abrir una terminal y saber dónde estás

Objetivo: ejecutar comandos en la carpeta correcta.

  • Windows 11: tecla Windows → escribe PowerShell → abre “Windows PowerShell” o “Terminal”.
  • macOS: abre “Terminal” desde Aplicaciones o Spotlight.
  • Linux: abre la terminal de tu distribución.
pwd
ls

En Windows, pwd y ls funcionan en PowerShell. En CMD clásico se usan cd y dir.

Para entrar en la carpeta de tu proyecto:

cd ruta/a/tu/proyecto

Resultado esperado: la terminal muestra la ruta de tu proyecto. Todo lo que instales a nivel de proyecto quedará dentro de esa carpeta.

3

Ejecutar la CLI con npx

Objetivo: lanzar la herramienta sin instalarla permanentemente.

npx busca el paquete skills en npm, lo descarga temporalmente o usa una copia en caché y lo ejecuta. Es el método recomendado para empezar.

npx skills
npx skills --help
npx skills --version

Resultado esperado: un menú interactivo, un mensaje de ayuda o un número de versión. La primera vez, npm puede preguntar si deseas instalar el paquete temporalmente: confirma con “y”.

VERIFICAR que --version existe en tu versión. Si no, usa --help.

4

Descubrir Skills antes de instalar

Objetivo: encontrar candidatas y evaluarlas críticamente.

  1. Abre skills.sh.
  2. Usa el buscador o los filtros por categoría.
  3. Haz clic en una Skill para ver su descripción, repositorio de origen y, si está disponible, el comando de instalación sugerido.
  4. Anota el origen, normalmente algo como owner/repositorio o una URL de GitHub.

También puedes explorar un repositorio directamente en GitHub y buscar archivos SKILL.md en sus carpetas.

npx skills search "revisión de código"

VERIFICAR la existencia y sintaxis exacta del subcomando search. Si no existe, el menú interactivo de npx skills puede incluir una opción de búsqueda o exploración.

Qué comprobar antes de instalar

  • ¿La description coincide claramente con la tarea que quieres resolver?
  • ¿El procedimiento es compatible con tu proyecto y tu lenguaje?
  • ¿Depende de herramientas que tu agente no tiene?
  • ¿El repositorio parece mantenido y el autor es identificable?
  • ¿Has leído el contenido completo, no solo el título?
5

Instalar una Skill

Objetivo: copiar la Skill a la carpeta correcta de tu agente.

El patrón general documentado es:

npx skills add <origen> [opciones]

Resultado esperado: un mensaje de confirmación y una nueva carpeta con el SKILL.md en la ruta correspondiente al agente elegido.

Escenario A — Instalar desde un repositorio completo de GitHub 
npx skills add owner/repositorio

Si el repositorio contiene varias Skills, la CLI puede abrir un modo interactivo para que elijas. Usa las flechas y la barra espaciadora o Enter para seleccionar.

Escenario B — Instalar desde una URL completa 
npx skills add https://github.com/owner/repositorio

Equivale al anterior, usando la URL que copiaste del navegador.

Escenario C — Instalar una Skill concreta dentro de un repositorio 
npx skills add owner/repositorio/ruta/a/la/skill

Evita el menú interactivo si el repositorio contiene varias Skills. VERIFICAR si la subruta se indica con / o con un flag como --path.

Escenario D — Instalar desde una ruta local 
npx skills add ./mi-skill-local
npx skills add /ruta/completa/a/mi-skill-local

Útil para probar una Skill propia antes de publicarla.

Escenario E — Elegir agente y alcance 
npx skills add owner/repositorio --agent <tu-agente>
npx skills add owner/repositorio --global
npx skills add owner/repositorio --agent <tu-agente> --global

VERIFICAR los nombres exactos de los flags. --agent y --global son el patrón habitual, pero deben confirmarse con --help.

De proyecto: ejecuta el comando dentro de la carpeta del proyecto. Global: usa el flag correspondiente o consulta la documentación.

Escenario F — Varias Skills y modo no interactivo 
npx skills add owner/repositorio --skill nombre-skill-1 --skill nombre-skill-2
npx skills add owner/repositorio --all
npx skills add owner/repositorio --yes

VERIFICAR la existencia y sintaxis de --skill, --all y --yes. El modo no interactivo es útil para scripts reproducibles, pero debe usarse solo cuando sepas exactamente qué se instala.

Verificación tras instalar

  1. Localiza la carpeta de instalación de tu agente (ver paso 6).
  2. Comprueba que existe una subcarpeta con el nombre de la Skill.
  3. Abre el SKILL.md y confirma que el contenido es el esperado.
  4. Si tu CLI lo permite, lista las Skills instaladas:
npx skills list

VERIFICAR el nombre exacto del subcomando de listado.

8

Actualizar, mantener y eliminar Skills

Objetivo: evitar que tu colección se vuelva obsoleta o insegura.

  1. Lista las Skills instaladas y anota su procedencia.
  2. Antes de actualizar una Skill crítica, revisa el historial de cambios del repositorio de origen.
  3. Prueba la actualización primero en un proyecto no crítico.
  4. Ejecuta la actualización:
npx skills update <nombre-skill>
npx skills update --all

VERIFICAR si existe outdated o --all. Si no, actualiza una por una.

  1. Verifica el comportamiento con una tarea representativa.
  2. Elimina las Skills que ya no uses:
npx skills remove <nombre-skill>

Precaución: no automatices actualizaciones desatendidas en proyectos críticos. Una actualización puede cambiar el comportamiento del agente sin que lo hayas revisado.

Cómo usa el agente una Skill instalada

El agente suele escanear las carpetas de Skills, leer las cabeceras y construir un índice ligero. Cuando tu tarea coincide con una description, carga el contenido completo y lo aplica. Si el agente ignora una Skill, revisa la ruta, la descripción, la formulación de tu petición y si hay demasiadas Skills compitiendo.

No todos los agentes activan, interpretan o priorizan las Skills de la misma manera. Las reglas generales describen el comportamiento típico del ecosistema; el comportamiento exacto de tu agente debe confirmarse en su documentación oficial.

Práctica: proyectos guiados y creación de Skills

La teoría no basta. Estos proyectos te llevan desde instalar una Skill existente hasta publicar una biblioteca propia y diseñar una política de uso profesional.

Cómo escribir instrucciones que funcionan

Mal ejemplo

description: Ayuda con textos.

Problema: no dice dominio, acción, tono ni cuándo usarla. El agente no sabe cuándo activarla.

Buen ejemplo

description: Revisa textos en español para publicaciones de blog, corrigiendo ortografía, gramática y adecuando el tono a un estilo profesional pero cercano. Úsala cuando el usuario pida "revisa este texto", "corrige este artículo" o pegue un borrador de blog.

Por qué mejora: incluye dominio, acción, tono y frases disparadoras literales.

De instrucción ambigua a instrucción verificable
DeficienteProblemaMejorada
“Resume el texto de forma adecuada.”“Adecuada” no está definido.“Resume en un máximo de 120 palabras, conservando cifras, fechas y nombres propios. No añadas opiniones ni información que no esté en el original.”
“Hazlo bien.”No es comprobable.“Incluye al menos un ejemplo y no superes las 150 palabras.”
“Sé breve pero incluye todos los detalles.”Contradicción.“Incluye solo los detalles necesarios para tomar una decisión; máximo 5 viñetas.”

Proyecto 1 — Instalar y utilizar una Skill existente

Objetivo: completar tu primer ciclo real de instalación y uso.

Nivel: principiante.

  1. Crea una carpeta de práctica: 
    mkdir practica-skills
cd practica-skills
  2. Busca en skills.sh una Skill real que te resulte útil.
  3. Anota su origen y revisa su SKILL.md en GitHub.
  4. Instálala para tu agente: 
    npx skills add owner/repositorio --agent <tu-agente>
  5. Verifica que el archivo está en la carpeta correcta.
  6. Abre una conversación nueva con tu agente y pide una tarea que coincida con la description.
  7. Observa si aplica el procedimiento.

Resultado esperado: el agente responde siguiendo la estructura o los criterios de la Skill.

Si el agente no la usa, revisa la ruta, el agente de destino y la formulación de tu petición antes de concluir que la Skill está rota.

Proyecto 2 — Evaluar tres Skills candidatas

Objetivo: practicar la evaluación crítica antes de instalar.

  1. Elige una tarea real.
  2. Busca al menos tres Skills candidatas.
  3. Completa esta tabla para cada una:
SkillOrigen¿Description clara?¿Procedimiento revisado?¿Señales de alerta?¿La instalarías?

Criterio de evaluación: la decisión debe basarse en criterios objetivos, no solo en el nombre o la popularidad aparente.

Proyecto 3 — Instalar dos Skills para el mismo agente

  1. Identifica el identificador de tu agente.
  2. Instala dos Skills distintas, dirigidas explícitamente a ese agente: 
    npx skills add owner/repo-uno --agent <tu-agente>
npx skills add owner/repo-dos --agent <tu-agente>
  3. Lista las Skills instaladas.
  4. Prueba una tarea real para cada una.

Resultado esperado: ambas activas y verificadas.

Error frecuente: que sus propósitos se solapen y el agente mezcle criterios. Si ocurre, ajusta las descripciones o elimina una.

Proyecto 4 — Crear una Skill sencilla desde cero

Objetivo: escribir, probar y refinar tu primera Skill.

  1. Elige un objetivo que quepa en una frase. Ejemplo: “redactar respuestas de atención al cliente con tono empático y breve”.
  2. Enumera 2–4 tareas concretas que cubrirá.
  3. Escribe 2–3 frases de ejemplo que un usuario diría y que deberían activarla.
  4. Define las entradas necesarias.
  5. Escribe el procedimiento numerado.
  6. Define criterios de calidad verificables.
  7. Crea la carpeta: 
    mkdir -p mis-skills/respuestas-atencion-cliente
  8. Escribe el archivo SKILL.md usando la plantilla siguiente.
  9. Instálala localmente para probarla: 
    npx skills add ./mis-skills/respuestas-atencion-cliente --agent <tu-agente>
  10. Pruébala con 3 peticiones reales.
  11. Ajusta la descripción y el procedimiento según los resultados.

Proyecto 5 — Skill avanzada con archivo auxiliar

Objetivo: crear una Skill más compleja que use una plantilla separada.

Estructura:

mis-skills/generador-de-contratos/
├── SKILL.md
└── plantilla-contrato.md
  1. En SKILL.md, referencia el archivo auxiliar: “Usa la estructura definida en plantilla-contrato.md como base”.
  2. Incluye una lista de comprobación final con al menos 5 puntos verificables.
  3. Instala y prueba con un caso sencillo y otro con datos incompletos.

Resultado esperado: el agente produce resultados consistentes y, ante datos incompletos, los señala en lugar de inventarlos.

Criterio de evaluación: si falta el nombre de una parte o una fecha, la Skill debe indicar “(sin asignar)” o pedir el dato, no rellenarlo con una invención.

Proyecto 7 — Publicar un repositorio con Skills

Objetivo: que otra persona pueda instalar tus Skills siguiendo solo tu documentación.

  1. Crea un repositorio en GitHub.
  2. Conecta tu carpeta local: 
    git remote add origin https://github.com/tu-usuario/mi-biblioteca-de-skills.git
git branch -M main
git push -u origin main
  3. Añade un archivo LICENSE adecuado.
  4. Completa el README.md con el comando de instalación real: 
    npx skills add tu-usuario/mi-biblioteca-de-skills
  5. Prueba la instalación desde otra carpeta o pide a otra persona que lo haga.

Criterio de evaluación: la instalación funciona sin explicaciones adicionales fuera del repositorio.

Proyecto 8 — Diseñar una política de Skills

Redacta un documento POLITICA-DE-SKILLS.md que incluya:

  • Quién puede instalar Skills de terceros y bajo qué revisión previa.
  • Con qué frecuencia se revisan actualizaciones.
  • Cómo se documenta cada Skill instalada: origen, agente, fecha, responsable.
  • Procedimiento ante una Skill sospechosa.
  • Convención de nombres y categorías.
  • Proceso de publicación de Skills propias.

Después, simula un incidente en un entorno aislado, sin credenciales reales, y comprueba que tu procedimiento funciona.

Módulos 13 y 14

Errores, seguridad y resolución de problemas

Este es el módulo de lectura obligatoria antes de instalar Skills de terceros de forma habitual. Una Skill es texto que un agente con capacidad de actuar puede interpretar como instrucciones de confianza.

1. Riesgos reales de instalar instrucciones de terceros

  1. Instrucciones que inducen a ejecutar comandos destructivos: borrar archivos, forzar sobrescrituras, modificar configuraciones críticas.
  2. Intento de extraer información sensible: pedir que se muestren archivos .env o que se incluyan claves API “para depuración”.
  3. Conexiones a servidores externos no deseados: enviar datos del proyecto fuera de tu control.
  4. Instrucciones ambiguas o de baja calidad: resultados incorrectos con apariencia de fiabilidad.
  5. Dependencias ocultas en archivos auxiliares: contenido que no se revisa con el mismo cuidado que el archivo principal.

2. Inspección obligatoria antes de instalar

  1. Abre el repositorio de origen en GitHub. No instales “a ciegas” solo por el nombre.
  2. Lee el SKILL.md completo, de principio a fin.
  3. Revisa todos los archivos auxiliares referenciados.
  4. Busca palabras de alerta: token, password, api key, secret, env, curl, borrar, delete, force, sudo, rm -rf, URLs externas poco conocidas.
  5. Revisa el historial de commits: actividad reciente, cambios sin explicación o abandono prolongado.
  6. Revisa quién es el autor u organización: ¿es identificable?, ¿tiene trayectoria?

3. Señales de alerta y señales positivas

Valorar la procedencia
Señal positivaSeñal de alerta
Organización o persona identificable y con trayectoria.Cuenta anónima recién creada.
Documentación clara y coherente.Descripción vaga que no explica el procedimiento.
Historial de commits activo y razonado.Un único commit masivo sin explicación.
Licencia claramente indicada.Ausencia total de licencia o información legal.
Comunidad visible: issues, estrellas, forks razonables.Repositorio aislado sin ninguna interacción.

4. Qué hacer ante una Skill sospechosa

  1. No la instales si tienes dudas razonables.
  2. Si ya la instalaste, elimínala con el comando de desinstalación y revisa manualmente la carpeta para confirmar que no quedan restos.
  3. Revisa si el agente llegó a ejecutar acciones basadas en esas instrucciones. Si usas Git, audita los cambios con git status y git diff.
  4. Revoca y rota cualquier credencial que pueda haber quedado expuesta.
  5. Documenta el incidente: qué Skill era, de dónde venía y qué hiciste.

Límite importante: ni la CLI ni el catálogo pueden garantizarte automáticamente que una Skill sea segura, correcta o esté libre de errores. Facilitan el descubrimiento y la instalación, pero la responsabilidad de revisar el contenido recae en ti.

Diagnóstico detallado: el agente no detecta la Skill
  1. Confirma la ruta exacta donde se instaló.
  2. Confirma que coincide con la ruta que documenta tu agente.
  3. Reinicia completamente la aplicación o el proceso del agente.
  4. Valida la cabecera YAML del SKILL.md.
  5. Prueba una petición que use literalmente palabras de la description.
  6. Si hay muchas Skills instaladas, reduce temporalmente el número para comprobar si hay competencia entre ellas.
Diagnóstico detallado: repositorio privado

Para instalar desde un repositorio privado, tu sistema debe estar autenticado con GitHub. Los mecanismos habituales son Git configurado con credenciales, SSH o un token de acceso personal. VERIFICAR qué mecanismo espera exactamente la CLI en su documentación.

Si el token caducó o no tiene permisos de lectura sobre ese repositorio, la instalación fallará aunque la URL sea correcta.

Preguntas frecuentes

¿Necesito saber programar para usar Skills?

No. Necesitas seguir procedimientos básicos de terminal, que este tutorial explica desde cero. Para crear Skills solo necesitas escribir texto estructurado en Markdown.

¿Una Skill puede dañar mi ordenador?

Una Skill en sí es texto. El riesgo real depende de las acciones que el agente esté autorizado a ejecutar basándose en ese texto. Por eso la inspección previa y el módulo de seguridad son obligatorios.

¿Todas las Skills funcionan con todos los agentes?

No necesariamente. Depende de qué agentes soporten el formato y de en qué carpeta se haya instalado. Verifica la documentación de tu agente.

¿Puedo tener la misma Skill instalada para varios agentes?

Sí, instalándola repetidamente y especificando cada agente de destino, si la CLI lo permite.

¿Qué pasa si edito una Skill mientras el agente la está usando?

Es recomendable iniciar una nueva sesión o conversación para que el agente vuelva a leer el archivo actualizado.

¿Qué hago si dos Skills se contradicen?

Identifica las dos Skills implicadas, decide cuál debe prevalecer y ajusta sus descripciones para que no se solapen, o elimina la que sobra.

Diez ideas para recordar

  1. La CLI instala; el agente aplica.
  2. Instalar la CLI no instala ninguna Skill.
  3. Una Skill es una carpeta con un SKILL.md.
  4. La description decide si la Skill se activa.
  5. Instalar en el agente equivocado es el error más común.
  6. Proyecto y global son alcances distintos.
  7. Los comandos exactos deben verificarse con --help.
  8. No instales Skills de terceros sin leerlas.
  9. Actualiza con cuidado y prueba antes en un entorno no crítico.
  10. Documenta qué tienes instalado, de dónde viene y con qué agente se probó.
